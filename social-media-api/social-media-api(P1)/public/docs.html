Overview

All API responses return JSON by default. Pass Accept: application/xml for XML responses.

Base URL http://localhost:3000/api

Authentication

Private routes require a user ID passed as a header to simulate authentication.

Header: X-User-Id: 1

Users

Manage user accounts — list, retrieve, create, update, and delete.

GET /api/users List all users ▶
ParameterTypeRequiredDescription
pageNumberOptionalPage number (default: 1)
limitNumberOptionalResults per page (default: 10)
{
  "success": true,
  "count": 3,
  "page": 1,
  "total_pages": 1,
  "data": [
    {
      "id": "1",
      "username": "traveler",
      "full_name": "Karma",
      "bio": "Travel photographer",
      "created_at": "2023-01-15"
    }
  ]
}
GET /api/users/:id Get a user by ID ▶
ParameterTypeRequiredDescription
idStringRequiredUser ID (URL param)
{ "success": true, "data": { "id": "1", "username": "traveler", ... } }
POST /api/users Create a new user ▶ 
{
  "username": "new_traveler",   // required
  "email":    "new@example.com", // required
  "full_name": "New Traveler",
  "bio":      "Adventure seeker"
}
Status: 201 Created
{ "success": true, "data": { "id": "4", "username": "new_traveler", ... } }
PUT /api/users/:id Update a user ▶
🔒 This route simulates authentication (no header required for users).
{ "bio": "Updated bio", "full_name": "Updated Name" }
DELETE /api/users/:id Delete a user ▶ 
Status: 200 OK — { "success": true, "data": {} }

Posts

Create and manage photo posts. Private write routes require X-User-Id header.

GET/api/postsList all posts (paginated)▶
Query params: page, limit — Returns posts enriched with author user data.
GET/api/posts/:idGet a single post▶
Returns post enriched with author user data.
POST/api/postsCreate a new post▶
🔒 Requires header: X-User-Id: <userId>
{ "caption": "My new post!", "image": "https://example.com/photo.jpg" }
PUT/api/posts/:idUpdate a post▶
🔒 Requires X-User-Id header. Must own the post.
{ "caption": "Updated caption" }
DELETE/api/posts/:idDelete a post▶
🔒 Requires X-User-Id header. Must own the post.

Comments

Nested under posts. Comments are retrieved and created via the post context.

GET/api/posts/:postId/commentsGet all comments for a post▶
Returns list of comments with author user info.
GET/api/comments/:idGet a single comment▶
Returns single comment by ID.
POST/api/posts/:postId/commentsAdd a comment▶
🔒 Requires X-User-Id header.
{ "text": "Great photo!" }
PUT/api/comments/:idUpdate a comment▶
🔒 Requires X-User-Id header. Must own the comment.
DELETE/api/comments/:idDelete a comment▶
🔒 Requires X-User-Id header. Must own the comment.

Likes

Like and unlike posts. Nested under the post resource.

GET/api/posts/:postId/likesGet all likes for a post▶
Returns list of likes with count.
POST/api/posts/:postId/likesLike a post▶
🔒 Requires X-User-Id header. Cannot like twice.
DELETE/api/posts/:postId/likesUnlike a post▶
🔒 Requires X-User-Id header.

Followers

Follow/unfollow users and retrieve follower/following lists.

GET/api/users/:userId/followersGet a user's followers▶
Returns list of users who follow :userId.
GET/api/users/:userId/followingGet who a user follows▶
Returns list of users that :userId is following.
POST/api/users/:userId/followersFollow a user▶
🔒 Requires X-User-Id header. Cannot follow yourself.
DELETE/api/users/:userId/followersUnfollow a user▶
🔒 Requires X-User-Id header.
